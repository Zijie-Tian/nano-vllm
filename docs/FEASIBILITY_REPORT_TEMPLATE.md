## 模板使用说明

### 必填章节

所有报告必须包含以下章节，不可省略：

| 章节 | 优先级 | 说明 |
|------|--------|------|
| Executive Summary | **必填** | 必须包含可行性评分 (X/10) |
| 详细设计 (§1) | **必填** | 包含伪代码或系统架构图 |
| 相关工作 (§2) | **必填** | 至少引用 3 篇相关文献 |
| 理论分析 (§3) | **必填** | 包含量化对比表 |
| 实现复杂度 (§4) | **必填** | 包含时间和资源估计 |
| 潜在风险 (§5) | **必填** | 包含 corner cases |
| COMPASS 结合点 (§6) | **必填** | 具体到文件和函数级别 |
| 结论 (§9) | **必填** | 必须包含可行性评分和 next steps |

### 可选章节

| 章节 | 何时包含 |
|------|----------|
| 量化可行性估计 (§7) | 有具体模型配置可分析时 |
| 实施建议 (§8) | 方案评分 >= 6/10 时 |

### 可行性评分标准

| 评分 | 含义 | 建议行动 |
|------|------|----------|
| 9-10 | 高度可行，风险极低 | 立即实施 |
| 7-8 | 可行，有可控风险 | 实施原型验证 |
| 5-6 | 有条件可行，需进一步验证 | 先做 PoC |
| 3-4 | 可行性存疑，风险较高 | 仅在无更好方案时考虑 |
| 1-2 | 基本不可行 | 放弃或大幅修改 |

### 写作风格要求

1. **中英混排**：技术术语用英文，说明性文字用中文
2. **量化为主**：尽量给出数字而非定性描述（"减少 40%" 而非 "显著减少"）
3. **伪代码必须可执行**：给出的伪代码应能直接改写为 Python
4. **表格化对比**：多方案对比必须用表格
5. **风险分级**：使用 高/中/低 三级
6. **引用规范**：每篇引用附上 URL 和一句话说明
