# Feasibility Report Rule

## 适用范围

当 codex-deep-thinker agent 被用于**评估方案可行性**时，必须遵循此规则。

## 强制要求

### 1. 使用标准模板

所有可行性分析报告**必须**按照 `docs/FEASIBILITY_REPORT_TEMPLATE.md` 中的模板格式编写。

### 2. 可行性评分是刚需

每份报告**必须**包含：
- Executive Summary 中的 **可行性评分 (X/10)**
- 结论章节中的 **评分理由**（✅/⚠️/❌ 分类）

不包含可行性评分的报告视为不完整。

### 3. 必填章节

以下章节不可省略：

| 章节 | 要求 |
|------|------|
| Executive Summary | 可行性评分 + 关键优势 + 主要风险 |
| 详细设计 (§1) | 含伪代码 |
| 相关工作 (§2) | ≥ 3 篇引用 |
| 理论分析 (§3) | 含量化对比表 |
| 实现复杂度 (§4) | 含时间估计 |
| 潜在风险 (§5) | 含 corner cases |
| COMPASS 结合点 (§6) | 具体到文件级 |
| 结论 (§9) | 评分 + next steps |

### 4. 输出位置

- 报告保存在指定的 `docs/` 子目录下
- 文件命名：`XX_方案简称.md`（如 `01_head_aware_budget.md`）

### 5. 评分标准

| 评分 | 含义 |
|------|------|
| 9-10 | 高度可行，立即实施 |
| 7-8 | 可行，需原型验证 |
| 5-6 | 有条件可行，需 PoC |
| 3-4 | 风险较高，慎重考虑 |
| 1-2 | 基本不可行 |
